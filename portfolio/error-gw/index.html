/ SUMMARY

日常に潜む「Error」

毎日接しているのにも関わらず、実態を持たず見過ごされがちな「Error」を、MR（Merged Reality）を通じて可視化し、
それが私たちの日常を停めてしまう怖さを表現することで、その重大さを感じさせる作品である。


展示空間には、MR体験が可能なVRゴーグル（Meta Quest 3）のほか、歩行者用押しボタン、 改札ICリーダーが設置されている。


ゴーグルを装着した鑑賞者は、「ボタンを押す」「スマートフォンをかざす」という日常の動作をきっかけに、
普段見えない世界に入り込んでいく。


そして「Error」が顕れる。横断歩道で青信号を待っていると突然、木の成長に「Error」が見え、
プラットフォームで電車を待っていると「Error」が聞こえてくる。

/ CONCEPT: ERROR

日常に潜む「エラー」を垣間見る

日常にある道具は、特定の役割と結果に結びつけられている。
歩行者用押しボタンは信号を切り替えるためにあり、私たちはボタンを押せば青信号になると考える。
この操作と結果の関係を、普段疑うことはほとんどない。


「Crosswalk」では、この慣れた関係に「エラー」を起こしている。
鑑賞者が横断歩道のVR空間に入り、青信号を待っていると、信号が切り替わる代わりに、目の前から大きな緑色の木が生える。
これは、緑色の信号を「青信号」と呼ぶ日本語の矛盾を、風景の異変として置き換えたものである。


木は次第に紅葉し、赤信号を思わせる姿へと変化する。
そこから落ちた葉は、数秒後に一定の確率で、カラーコーンや「とまれ」標識へ置き換わる。
いずれも赤色で、「止まれ」を連想させるオブジェクトである。
やがて風が吹き、紅葉した葉が鑑賞者へ降り注ぎ、空間全体がこれらのオブジェクトに侵食されていく。


ボタンを押せば信号が変わるという日常の因果関係は、色や言葉、オブジェクトが持つ意味へと分解され、予想外の現象として再構成される。
「Error」は、合理的な世界を否定する作品ではない。
見慣れた道具の役割を一度ずらすことで、私たちが無意識に受け入れている日常のルールを、別の角度から捉え直すための体験である。

/ TECH

Gaussian Splatting

https://antimatter15.com/splat/

Gaussian Splatting（以下GS）は、中心から広がるもやのような粒を空間に撒く（スプラット）ことによって3D空間を表現する、新たなボリューメトリックレンダリングの手法。

リアルタイムレンダリングに長けており、左の外部サイトではGSをブラウザ上で閲覧することができる。

さまざまな角度から観察することで、このモデルが粒の集合体であることがわかるかと思う。

なぜGSなのか

この作品は日常風景を扱い、それを歪めることで生まれる体験である。

GSで再現されたシーンには空気感が生まれる。ここで通常のメッシュモデルを使用してしまうと

Quest3向けGSレンダラーの実装

開発環境はUnity（C#）。展示での安定性を優先し、Quest3単体で動くアプリケーションの開発を目指した。

しかし既存実装はPCVR前提のものが多く、この制作に向いたものを見つけることはできなかった。

そのため、Questスタンドアロン向けにGSレンダラーを自前で制作することにした。


.splatファイルバイナリのパース、展開からカスタムシェーダによる描画まで、パイプライン全体の設計・実装をゼロから行なった。

DrawIndirectによる一括描画、Compute ShaderによるZソート、ボクセル単位の距離LODを組み合わせることで、

QuestのGPU制約の中でリアルタイム描画を実現した。

Unity Editor上で自作GSが表示されている様子。


厳しい制作スケジュールで体験を完成させるため、エディタ上での扱いやすさも重視した設計になっている。

ネットワークとインタラクション

この作品には、VR体験の起点として物理的な入力が置いてある。

Crosswalkは展示されている歩行者ボタンを押すことで始まるが、この歩行者ボタンはESP-32を内蔵した無線デバイスになっており、

Raspberry Pi、Node.jsで構成したHTTPサーバーを介してQuestとの通信が成立している。

この「物理的な存在」と 「バーチャルな体験」のつながりは、この作品のアイデンティティのひとつだ。

構築したネットワークの概念図。※簡略のためClosswalkに限って図示している


すべてのデバイス（Quest・ 歩行者ボタン（ESP-32）・HTTPサーバー（Raspberry Pi））は同じLANに無線接続されている。

ESP-32は押しボタンの状態を定期的にサーバーへ送信しており、サーバーはその状態を保持する。

Questはサーバーをポーリングしており、ボタンの押下をトリガーとして体験を開始する。
